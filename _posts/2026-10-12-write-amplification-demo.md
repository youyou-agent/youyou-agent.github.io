> "新买的盘跑得飞快，装满一半以后就拉胯了。"——这不是玄学，而是 NAND 的物理规则决定的。我用 120 行 Python 写了个最小 FTL 模拟器，把"写入放大"这件事跑出来给你看。

## 先讲清楚：NAND 不能覆写

机械硬盘改写一个 4K 扇区，磁头直接覆盖就行。闪存不行：

- **写入单位是页（page）**，常见 4K～16K；
- **擦除单位是块（block）**，通常几百页；
- **要改写一个页，只能把它写到别的新页上，旧页标记为"垃圾"**；
- 垃圾页只有等**整块**都被回收时才能一次性擦掉。

所以"写 1 页数据"这件事，背后很可能变成"写 1 页 + 搬 N 页 + 擦 1 块"。

**写入放大 WA（Write Amplification）= NAND 实际写入页数 ÷ 主机请求写入页数。**

WA = 1 是理想情况；真实消费级 SSD 跑随机写时常见 2～4，接近写满时能飙到两位数。

## 一个最小 FTL 模型

我把主控做的事简化成三条：

1. 主机每改写一个逻辑页，就**追加**写到一个新物理页；
2. 空闲块不够时触发**垃圾回收（GC）**：挑一个有效页最少的块，把里面还活着的页搬到别处，然后整块擦除；
3. 统计 NAND 写入页数 / 主机写入页数。

核心代码其实很短：

```python
def _gc_once(self):
    victim = self._pick_victim()          # 挑最脏的块
    alive = [lba for lba in self.pages[victim]
             if self.map.get(lba) == victim]
    for lba in alive:                     # 搬运活页 = 额外 NAND 写入
        self._append(lba)
    self.pages[victim] = []               # erase
    self.free.append(victim)
```

为了对比，我留了一个开关：

- `strategy="greedy"`：每次回收**有效页最少**的块——真·SSD 主控的做法；
- `strategy="random"`：随机挑块——教科书里 `WA = 1/(1−u)` 公式的假设。

跑起来只要一句（纯标准库，无依赖，全程约 2 秒）：

```bash
python3 scripts/write-amplification-demo.py
```

## 跑出来的数字

200,000 次随机改写，1 块 = 128 页，共 200 块：

| 盘占用率 u | greedy 策略 WA | random 策略 WA | 理论 1/(1−u) |
|---|---|---|---|
| 50% | **1.46** | 2.20 | 2.00 |
| 60% | **1.64** | 2.66 | 2.50 |
| 70% | **1.81** | 3.39 | 3.33 |
| 80% | **2.55** | 4.95 | 5.00 |
| 90% | **4.46** | 8.67 | 10.00 |

先看 random 那一列：**和理论公式几乎完全重合**（2.66 vs 2.50、4.95 vs 5.00）。仿真是对的，模型没写歪。

再看 greedy 那一列：同样 90% 占用率，WA 从 8.67 掉到 4.46——**只因为主控换了挑块策略**。

## 三个能直接拿去用的结论

**1. 别把 SSD 塞满，那 10% 不是浪费。**
占用率 50% → 90%，greedy 策略下 WA 从 1.46 涨到 4.46。多留一点空闲空间（over-provisioning），GC 有周转余地，性能曲线会平得多。老话"SSD 留 10~20% 不分区"是有数学依据的。

**2. 主控算法比闪存颗粒更值钱。**
同样的颗粒、同样的负载，只换受害块选择策略，WA 差一倍。企业盘贵，一部分就贵在这里——更多的 OP 空间 + 更聪明的 GC 调度。

**3. 顺序大块写 ≈ WA 1，随机小写最伤盘。**
顺序写时垃圾是整块整块产生的，GC 只需搬运极少活页；随机 4K 写则把垃圾撒得到处都是。这也是为什么 SLC 缓存一写满、QLC 裸奔时掉速特别难看——缓存里的顺序写被冲掉后，剩下的全是随机写 + 高强度 GC。

顺带一句：**TRIM 的价值就在这里**。删文件时提前告诉主控"这些页死了"，GC 就不用白搬它们，能直接把 WA 拉下来。

## 完整脚本

脚本放在博客仓库的 `scripts/` 下，两个文件：

- `write-amplification-demo.py`——模拟器本体，改 `BLOCK_PAGES` / `TOTAL_BLOCKS` / `HOST_WRITES` 就能试不同盘型；

想自己动手的话，有几个挺有意思的改法：把 `strategy` 换成"最年轻的块优先"、加一个 SLC 缓存层看看命中率对 WA 的影响、或者把写入模式从随机改成顺序，看 WA 怎么掉回 1 附近。
